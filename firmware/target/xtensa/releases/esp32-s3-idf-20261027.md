commit `a1a3ece0b180854e5539ad89e3967c6e203d7241`, on 2026-10-27. Everything here came

the version embedded in the image is `a1a3ece0b1-261027` with no local-modification

This is not an official Rockbox release. It is the first packaged build of a port that
is meant to be merged upstream — see `README.md` (copied into this folder) for what the
port is, what works and what the hardware can't do.

## Flashing

Put the device in download mode first: hold **BOOT** through the small hole on the
back, tap **RESET** (or plug in USB while holding BOOT), then release.

With <https://esptool.spacehuhn.com/> in a Chromium-based browser:

1. Connect the device.
2. Add `rockbox-flash.bin` at offset **`0x0`**.
3. Delete any rows that have an offset but no file — they make the flash fail.
4. Flash. When it reports done, power-cycle: unplug USB, then press the power button
   to start Rockbox.

From a shell instead:

```sh
esptool --chip esp32s3 --port /dev/ttyACM0 write_flash 0x0 rockbox-flash.bin
```

If you'd rather place the pieces: `bootloader.bin` at `0x000000`,
`partition-table.bin` at `0x008000`, `rockbox.esp32s3` at `0x010000`.

Flashing rewrites the partition table. Flashing the stock MeowKit firmware back
restores its own, and the SD card is untouched either way.

## SD card

Format a card as FAT32 with one partition and unzip into its **root** — `.rockbox/` has
to sit at the root, not inside a folder:

```sh
unzip rockbox.zip        -d /mnt/card
unzip rockbox-fonts.zip  -d /mnt/card   # optional
```

Then copy music on. First boot builds the database from the collection, so the first
browse is slower than the ones after it.

## What is verified

Everything below was tested on the device: boot to the root menu, playback of FLAC /
MP3 / OGG / Opus and the rest of the codec set at 44.1, 48 and 96 kHz, resume from idle,
the touchscreen, the stick and buttons, backlight fading and the LCD sleep and shutdown
states, recording from the microphone, USB mass storage (which holds on plug), USB DAC
mode, themes, fonts, voice prompts, album art, plugins and games, SD storage with
dircache and the tag database, charging and battery voltage from the AXP173, the
PCF8563 RTC, and a long press of the power button producing a clean shutdown that
flushes buffers, saves settings and closes the card.

## What is not

- **Bluetooth audio is impossible on this chip**, not pending work: the ESP32-S3 radio
  is Bluetooth Low Energy only, with no BR/EDR baseband for A2DP, and LE Audio needs
  isochronous channels this core config doesn't have.
- **Output is mono.** The ES8311 is a single-channel codec, so both the headphone jack
  and the speaker are mono. Stereo files are summed.
- **The battery gauge reports voltage.** The AXP173 coulometer counters are read and
  exposed, but not yet scaled to a percentage — that needs one calibration run.
- **No long soak.** Nothing in this build has been left running unattended for hours.
- Codecs and plugins execute from PSRAM, which works but is slower than internal RAM;
  `mpegplayer` runs around 11 fps on a full-frame encode and its frame rate is largely
  set by how the video was encoded.

## Reproducing this build

```sh
git checkout esp32-s3-idf-20261027
docker build -f tools/docker/Dockerfile --target rb-env \
  --build-arg RB_BRANCH=esp32-s3-idf-20261027 \
  -t rockbox-meowkits3:esp32-s3-idf-20261027 .
docker run --rm -e RELEASE=esp32-s3-idf-20261027 \
  -v "$PWD/release/esp32-s3-idf-20261027:/out" \
  rockbox-meowkits3:esp32-s3-idf-20261027
```

The container installs the toolchain and ESP-IDF with the repository's own
`tools/rockboxdev.sh --target=e`, runs the memory-layout guard and the image
verification before anything is copied out, and writes `tools/docker/README.md` for the
details.
