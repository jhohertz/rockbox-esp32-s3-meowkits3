# Rockbox for the MeowKit ESP32-S3 — release `esp32-s3-idf-20261029`

Built from tag [`esp32-s3-idf-20261029`](https://gitea.max.optiplexus.org/jhohertz/rockbox/src/tag/esp32-s3-idf-20261029)
on 2026-10-29, by one reproducible container run. This is the second packaged build of
the port; it supersedes [`esp32-s3-idf-20261027`](esp32-s3-idf-20261027.md) and is a
delta of 27 commits over it, all of them on things that were broken or unmeasured in
the first one.

This is not an official Rockbox release. It is a working fork meant to be merged
upstream: core files carry only weak seams that leave every other target's behaviour
untouched. `README.md` (copied into this folder) describes the port itself.

## Files

| File | What it is |
|---|---|
| `rockbox-flash.bin` | **Flash this.** Bootloader + partition table + app merged into one image that starts at offset `0x0` |
| `rockbox.zip` | Card payload: the codec set, plugins plus Lua plugins, languages, the English voice pack, themes, icons and WPS files |
| `rockbox-fonts.zip` | 88 fonts, deliberately not in `rockbox.zip` |
| `rockbox-manual.pdf` | The per-target manual, built from this tree: this device's keys, settings and quirks |
| `rockbox.esp32s3` | The app image alone, for people placing the three pieces themselves |
| `bootloader.bin`, `partition-table.bin`, `flash_args` | The other two pieces, and the offset list ESP-IDF's own flash step uses |
| `espverify.txt` | `esptool image_info` output: segment table, load addresses, checksum and validation hash |
| `rockbox.map` | Linker map, so the memory-layout guard can be re-run by anyone without a toolchain |
| `rockbox.elf` | The linked ELF — symbols and debug info, so a crash address printed on the serial console can be resolved without rebuilding anything |
| `build-manifest.txt` | Release label, commit, dirty count, IDF/toolchain/host compiler versions, build time |
| `SHA256SUMS` | Checksums for everything above |

Sizes and hashes are deliberately not written down here — they are only knowable after
the build, and they ship in `SHA256SUMS` beside the artifacts. `SHA256SUMS` is a checksum
of *this run's bytes*, not a content fingerprint: rebuilding the same tag produces a
payload whose file listing and per-file sizes are identical, but the archive bytes differ,
because a nested zip records timestamps, and the firmware embeds its build date.

## Flashing

Put the device in download mode first: hold **BOOT** through the small hole on the back,
tap **RESET** (or plug in USB while holding BOOT), then release.

With <https://esptool.spacehuhn.com/> in a Chromium-based browser:

1. Connect the device.
2. Add `rockbox-flash.bin` at offset **`0x0`**.
3. Delete any rows that have an offset but no file — they make the flash fail.
4. Flash. When it reports done, power-cycle: unplug USB, then press the power button to
   start Rockbox.

From a shell instead:

```sh
esptool --chip esp32s3 --port /dev/ttyACM0 write_flash 0x0 rockbox-flash.bin
```

If you'd rather place the pieces: `bootloader.bin` at `0x000000`,
`partition-table.bin` at `0x008000`, `rockbox.esp32s3` at `0x010000`.

Flashing rewrites the partition table. Flashing the stock MeowKit firmware back restores
its own, and the SD card is untouched either way.

## SD card

Format a card as FAT32 with one partition and unzip into its **root** — `.rockbox/` has
to sit at the root, not inside a folder:

```sh
unzip rockbox.zip        -d /mnt/card
unzip rockbox-fonts.zip  -d /mnt/card   # optional
```

Then copy music on. First boot builds the database from the collection, so the first
browse is slower than the ones after it. Cards are FAT32 only — exFAT is supported
nowhere in Rockbox, and cards of 64 GB and up are commonly formatted exFAT by default.

## What changed since `esp32-s3-idf-20261027`

**The microphone works properly.** The ES7210 has two gain stages — its own PGA and
Rockbox's software gain — and the driver was using one of them badly: register `0x41`
was written as `0x70`, whose extra bits put the PGA into a state that killed it, and
`REG08`'s speed bit is bit 1 rather than the bit the code cleared. Recording level is now
measurable rather than hoped for, proven by a recorded-RMS comparison rather than by
reading the datasheet again. The capture path also got its bus ownership sorted: the I2S
receiver owns its rate, and only one owner drives the bus at a time, so recording and
playback cannot both claim the same divider.

**The battery percentage is measured, not inferred.** The AXP173's coulometer counters are
converted with a scale that was checked against hardware — the reference library's
constant is wrong by a factor of 65536, and the chip said so — and the gauge now moves by
charge actually transferred, anchored to the voltage-derived percent at first reading.
Three AXP173 whole-register writes were also clobbering fields they weren't about, one of
which is how a board that had been charging overnight could read 83 %. `battery_bench`
logs cumulative mAh charged and discharged, marks the charge-to-discharge switch with a
labelled line, and reads `D` for discharge instead of a `-` that meant three different
things.

**Doom plays.** It used to run out of memory mid-level and die. Four separate allocations
were found by logging the memory zone rather than guessing: each sound effect was read
twice, `I_InitGraphics()` never released the screen buffer it was given, the screen-wipe
transform kept a third full-panel buffer in the game's memory pool, and the directory
cache held a 1 MB floor regardless of its configured limit. Its error path also returned
into a NULL caller instead of leaving. Controls were remapped for a first-person shooter
— stick walks and turns, `A` fires, `B` opens doors and uses switches, and the touch grid
carries escape, map, weapon, menu confirm, autorun and strafe. Sound is on by default:
the plugin's own settings table had it off, and the plugin deletes its config file before
every launch, so no menu change could ever persist. Doom has no music on any Rockbox
port — the music functions are upstream stubs — so it is sound effects only.

**Build hygiene.** Rebuild rules now come from measurements instead of intentions:
dependency files are generated in a defined order, archives are rebuilt from scratch so a
stale object cannot survive, the ESP-IDF seed state has an owner and a stamp, and the
image-packaging goals work out of tree.

**New on the debug screen.** `Debug → View HW info` gained an arena row reporting the
allocatable static arena, which is what a plugin's memory limit actually is.

## What is verified

Device-verified: boot to the root menu, playback of the codec set at 44.1, 48 and 96 kHz,
resume from idle, the touchscreen, the stick and buttons, backlight fading and the LCD
sleep and shutdown states, recording from the microphone at a usable level, USB mass
storage, USB DAC mode, themes, fonts, voice prompts, album art, plugins and games, SD
storage with dircache and the tag database, charging and battery voltage, the battery
percentage moving with measured charge, the PCF8563 RTC, and a long press of the power
button producing a clean shutdown that flushes buffers, saves settings and closes the
card. Doom was played through its title screen, a level load, a screen wipe and gameplay,
with sound and with the new controls.

## What is not

- **Bluetooth audio is impossible on this chip**, not pending work: the ESP32-S3 radio is
  Bluetooth Low Energy only, with no BR/EDR baseband for A2DP, and LE Audio needs
  isochronous channels this core config doesn't have.
- **Output is mono.** The ES8311 is a single-channel codec, so both the headphone jack and
  the speaker are mono. Stereo files are summed.
- **The cell's capacity is still the datasheet's number.** The gauge measures charge
  transferred; how much charge the cell actually holds above the 3.3 V shutdown point is a
  run-to-shutdown measurement that has not finished yet. Until it does, the percent is
  honest about what has moved and approximate about what is left.
- **`battery_bench`'s discharge marker has not been used yet.** It exists for the run
  described above.
- **No long soak.** Nothing in this build has been left running unattended for hours; the
  overnight run that started after this tag was cut is the first one.
- Codecs and plugins execute from PSRAM, which works but is slower than internal RAM;
  `mpegplayer` runs around 11 fps on a full-frame encode and its frame rate is largely set
  by how the video was encoded.
- **This tag has been flashed, and only that much is verified.** It went in at `0x0` on
  2026-10-29 — esptool wrote 1,358,832 bytes and verified the post-write hash — and the
  device boots. The feature list above describes the port as it stands in this tree, not a
  re-run of every item against these exact bytes; the behavioral re-verification that
  matters after a flash is the long soak, which is running now.
- One hardware path is still unproven: the cache-maintenance trampoline that calls the
  ESP32-S3 ROM's `Cache_*` functions from hand-written assembly. It assembles, links and
  runs, but whether `rfe` restores correctly when `WINDOW_BASE` is pinned by hand is ISA
  behaviour that needs a bench test. Normal operation does not depend on it.

## Reproducing this build

```sh
git checkout esp32-s3-idf-20261029
docker build -f tools/docker/Dockerfile --target rb-env \
  --build-arg RB_BRANCH=esp32-s3-idf-20261029 \
  -t rockbox-meowkits3:esp32-s3-idf-20261029 .
docker run --rm -e RELEASE=esp32-s3-idf-20261029 \
  -v "$PWD/release/esp32-s3-idf-20261029:/out" \
  rockbox-meowkits3:esp32-s3-idf-20261029
```

The container installs the toolchain and ESP-IDF with the repository's own
`tools/rockboxdev.sh --target=e`, runs the memory-layout guard and the image verification
before anything is copied out, and writes `build-manifest.txt` and `SHA256SUMS` last, only
if every step succeeded. See `tools/docker/README.md` for the layers and the arguments.

If you mount a checkout over the container's own clone instead of letting it clone the tag
(`-v "$PWD:/src/rockbox"`), tell git the directory is safe first — a mounted host
checkout is owned by a different uid, and git refuses to read it otherwise, which leaves
the manifest saying `commit=unknown` and the image embedding an empty version string:

```sh
-e GIT_CONFIG_COUNT=1 -e GIT_CONFIG_KEY_0=safe.directory -e GIT_CONFIG_VALUE_0=/src/rockbox
```

`tools/docker/rb-build-artifacts.sh` now sets that itself for future runs.
